# Agent instructions

- This project is currently for brainstorming and planning only. Do not write code, scaffold applications, or implement prototypes unless the user explicitly changes that scope.
- Answer and write concisely, without unnecessary prose. Use plain language and explain unfamiliar terms.
- Record substantive discussion outcomes in Markdown (`.md`) files under `docs/`. Keep only these instructions and a documentation link at the project root.

## Documentation organization

- Use `docs/README.md` as the project overview and index. Link new documents from it.
- Start with a few files; split by topic only when it improves readability. Use short, descriptive, lowercase kebab-case filenames, such as `architecture.md` or `open-questions.md`.
- Update the existing topic document instead of creating duplicate notes or conversation transcripts. Keep one authoritative location for each idea and link to it elsewhere.
- Clearly distinguish proposals, assumptions, agreed decisions, and open questions. Record the rationale for decisions; mark superseded ideas when relevant.
- Write for humans: lead with the main point, use descriptive headings and short paragraphs, and use lists or tables when they make information easier to scan.
- Keep the overview and links current. Preserve useful context without repeating it, and never present an unresolved idea as a settled decision.
